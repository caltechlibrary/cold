
# Releasing **cold**

Three files are edited by hand. Everything else carrying a version number is
derived from `codemeta.json` and will be regenerated, so editing a derived file
is wasted work that the next build overwrites.

## Edit by hand

1. **`codemeta.json`** — the source of truth.
   - `version`
   - `dateModified` and `datePublished` — the release date
   - `releaseNotes` — one Markdown bullet per point, no leading `#` heading

2. **`htdocs/about.md`** — the application's About page, **not** generated by
   any Makefile target.
   - `version:` in the frontmatter
   - `date_released:` in the frontmatter
   - the `## cold X.Y.Z` section body, which is the same text as
     `codemeta.json`'s `releaseNotes`

   **It holds exactly one version section.** Every commit in its history has
   one; the previous release's notes are replaced, not accumulated. If you want
   a running history, that is a deliberate change of convention, not a
   correction.

3. **`TODO.md`** — the "Start here" section, so the next person opens the
   repository on the current state rather than the last release's.

## Derived — do not edit

| file | produced by |
|---|---|
| `version.ts` | `cmt codemeta.json version.ts` (`make version.ts`) |
| `CITATION.cff` | `cmt codemeta.json CITATION.cff` (`make CITATION.cff`) |
| `docs/*.1.md` | `make compile` — each binary's `--help`, so they carry the version only after a rebuild |
| `man/man1/*.1` | `make man`, from `docs/*.1.md`. Gitignored |
| `installer.sh`, `installer.ps1` | `make build`, pandoc over `codemeta.json` |
| `htdocs/about.html` | `build.ts`, from `htdocs/about.md` |
| `bin/`, `dist/` | build artifacts, gitignored |

## Order

```
edit codemeta.json, htdocs/about.md, TODO.md
make version.ts CITATION.cff     # cmt; regenerates the derived version files
deno task build                  # rebuild binaries so --help reports the new version
make compile                     # regenerate docs/*.1.md from --help
deno task test                   # 164 + 7, and the lint_imports gate
make release                     # clean, build, man, distribute_docs, dist/*
./release.bash                   # tags and pushes to GitHub
```

`make release` reruns most of the above; the point of doing `version.ts`,
`build` and `compile` first is to see the version propagate and to commit the
regenerated files as part of the release prep rather than discovering them in
the release commit.

## Traps

**`cmt` will not take a path.** `cmt codemeta.json htdocs/about.md` fails with
"unsupported format" — it writes a bare `about.md` into the current directory.
That is one reason `htdocs/about.md` is hand-maintained rather than wired into
the Makefile. The other is that CMTools is being retired in favour of
`codemetatools`, so this is not the moment to add a new `cmt` call.

**`cmt` is required for `make release` and for nothing else.** `make`,
`make test` and a deployment need no CMTools at all — see `deployment.md`. Do
not reintroduce it into the `build` path.

**`make` prunes `deno.lock`.** The sixteen `deno bundle` tasks pass
`--config tsconfig.json`, which rewrites the project lockfile to that config's
much smaller graph. A test run then restores it. Check `git diff deno.lock`
before committing a release and do not commit the pruned version; the complete
lock is the union of the app, test and check graphs.

**Regenerating `docs/*.1.md` needs a rebuild first.** They come from each
binary's `--help`, so running `make compile` against stale binaries writes the
*old* version number into all fourteen files.
